# 仕様変更ガード

`docs/requirements.md` は要件の SSOT。ここが古いまま実装が進むと、spec・コード・ドキュメントが乖離する。
**要件レベルの変更を含む依頼を受けたら、実装に着手する前にユーザーへ確認する。**

## 1. 要件レベルか実装詳細かを判定する

| 要件レベル（確認が必要） | 実装詳細（確認不要） |
|---|---|
| 新しい機能・画面・API エンドポイントの追加 | 既存要件を満たすための内部リファクタ |
| 既存 `FR-xx` / `NFR-xx` の挙動・受け入れ条件（AC）の変更 | 変数名・ファイル分割・テスト追加 |
| API 契約（ルート・zod スキーマ・エラー形式）の変更 | 実装の型定義やヘルパーの整理 |
| データモデル（テーブル・カラム・導出ロジック）の変更 | インデックス追加などの性能改善（挙動不変） |
| 優先度（P0/P1/P2）・スコープ（§2）の変更 | 文言の typo 修正 |
| `【要確認】` の確定、§21 前提・未決事項の解消 | ログ出力の調整 |
| 要件の削除・非スコープ化 | 既存 AC どおりに直すバグ修正 |

判断に迷う場合は「確認が必要」側に倒す。

まず現状を確認する:

```bash
grep -n "FR-\|NFR-\|【要確認】" docs/requirements.md | head -50
```

## 2. ユーザーに確認する

`AskUserQuestion` を使い、**何が要件レベルの変更にあたるのか**を具体的に示してから問う。

質問文の型:

> 今回の依頼には要件レベルの変更が含まれます（例: `FR-06 ドメイン登録` の AC に「登録前に確認ダイアログを出す」を追加）。
> `docs/requirements.md` を更新しますか？

選択肢（推奨順）:

1. **要件を先に更新してから実装**（推奨） — requirements.md を更新し、必要なら `docs/specs/<feature>.md` も揃えてから実装に入る
2. **実装のみ（要件は変えない）** — 既存要件の範囲内だとユーザーが判断した場合。要件は現状維持
3. **要件の更新のみ** — 実装は別 PR / 別タスクに分ける
4. **保留して要確認にする** — `【要確認】` として §21.2 に積み、決まるまで実装しない

回答を得るまで実装ファイルには触れない。並行して進められる調査（既存コードの確認など）は進めてよい。

## 3. 「更新する」と答えられたときの手順

1. 該当セクションを直す
   - `§4 機能要件` の `FR-xx` 本文と AC、`§5 非機能要件`
   - 影響範囲に応じて `§2 スコープ` / `§9 データモデル` / `§10 API 設計` / `§11 レジストリ連携`
   - 確定した `【要確認】` は本文から外し、`§21.2 未決事項` の該当行も消す
2. 要件 ID を守る
   - 新規要件は既存の最大番号の次を採番（`FR-19` など）。既存 ID の意味を変えない
   - 削除する要件は ID を再利用せず、削除した旨を残す
3. 末尾の `### 更新履歴` に 1 行追加し、版を上げる（例 `v0.1.1` → `v0.1.2`）。冒頭の表の `版` も揃える
4. 追随が必要なものを洗い出して提示する
   - `docs/specs/<feature>.md`（該当 FR を参照している spec）
   - 既存コード・テスト（変更した AC に対応する箇所）
   - 大きな設計判断を伴うなら `docs/adr/NNNN-<slug>.md` を追加
5. コミット・PR
   - `main` への直接 push は禁止。`docs/<slug>` または当該 `feat/<fr-id>-<slug>` ブランチで作業
   - Conventional Commits（例: `docs: FR-06 に登録前確認ダイアログの AC を追加`）
   - 実装と同じ PR に含めるか、要件だけ先に PR を出すかはユーザーに合わせる

## 4. やってはいけないこと

- 確認なしに `docs/requirements.md` を書き換える
- 確認なしに要件レベルの実装を進めて、後から requirements.md を追記する
- `【要確認】` を推測で確定させる
- 更新履歴・版番号を更新せずに本文だけ直す
- 要件 ID の番号を詰め直す・再利用する

## 5. 確認を省略してよい場合

- ユーザーが明示的に「要件は変えない」「requirements.md は触らないで」と言っている
- 同一セッションで既に同じ変更について確認済み（同じことを再度聞かない）
- 文書化済みの挙動へ戻すだけのバグ修正
